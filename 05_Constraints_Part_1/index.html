Course §2.2 · Constraints · Logical connectives

Combining conditions: ∧ means AND, ∨ means OR

A connective combines true/false statements. Here each X₁, X₂, X₃ has domain {0,1,2}.

∧ · AND: all conditions must hold

(X₁ < 2) ∧ (X₂ > 0)
∧ (X₃ < X₁)

This is the course CSP: satisfy all three rules together.

(1,0,0): false overall.
The middle rule fails; the others hold.

∨ · OR: at least one must hold

(X₁ = 1) ∨ (X₂ = 2)

An illustrative OR constraint.
Either part may hold; both may hold too.

(1,0,0): true overall.
The left part holds, so this OR holds.

A CSP requires an AND across its constraints. An individual constraint may contain OR. The OR example is a separate illustration, not an extra course rule.

Formal definition of a CSP

P = (𝓧, dom, 𝓒)

𝓧 = {X₁, …, Xₙ}

𝓧 is the variable set; n counts its variables.

𝓒 = {c₁, …, cₘ}

𝓒 is the constraint set; m counts its rules.

dom is a function

X ↦ dom(X)

For each variable X, dom returns its allowed-value set.

Each c ∈ 𝓒 has a scope contained in 𝓧. All values chosen for X must belong to dom(X).

P names the problem. Solving it means finding one or all total assignments that use allowed values and satisfy every constraint.

Mathematical definition · Constraint satisfaction

Which constraints can a context evaluate?

c ≡ A ⇔ scope(c) ⊆ vars(A)

A is an updatable partial assignment called context; vars(A) is the set of variables already assigned. Here ≡ means “can be evaluated in”, not “is true”. c ≡ A if all variables in c are present in A.

Enough input does not mean true

A={X₁=1, X₃=0}. For c: X₁=X₃,
c ≡ A holds, but ε(A[scope(c)],c)=0.

The set DFS checks now

𝓒e = {c ∈ 𝓒 | c ≡ A}

𝓒ₑ contains the rules whose scopes are complete. The bar | means “such that”.

⊆ means “is a subset of”. If a variable in scope(c) is missing, c ≢ A: the rule is pending, so plain DFS cannot evaluate it yet.

02 · Systematic solving

DFS solver: Backtracking

DFS_solver(𝓧, 𝓒, A):
    𝓒ₑ ← {c ∈ 𝓒 | c ≡ A}
    if some c ∈ 𝓒ₑ has ε(A[scope(c)],c)=0:
        return ∅
    if 𝓧 = ∅: return {A}
    choose X ∈ 𝓧; s ← ∅
    for x ∈ dom(X):
        s ← s ∪ DFS_solver(𝓧∖{X}, 𝓒∖𝓒ₑ,
                           A ∪ {X=x})
    return s

What changes in recursion?

𝓧: variables still to assign.

𝓒: rules still to check; 𝓒ₑ: rules checkable now.

A: partial context; s: set of solutions.

∖: remove from a set.
∪: combine sets.

Start with all variables and rules, and A=∅. Returning ∅ means no solutions from this branch; {A} contains one solution.

Consistency algorithms: filter before branching

DFS can be inefficient: it may try every value of B even when the chosen A has no possible partner.

DFS: discover failure four times

Rule A < B; both domains are {1,2,3,4}.

Choose A = 4, then try…Rule check
B = 14 < 1 ✗
B = 24 < 2 ✗
B = 34 < 3 ✗
B = 44 < 4 ✗

Consistency: remove the dead end first

dom(A): {1,2,3,4}

No allowed B is greater than 4.
Remove 4 before branching on A.

One domain check rules out every completion with A=4, while keeping all solutions.

Consistency algorithms remove values that cannot satisfy a constraint. Repeating these deductions as domains change is constraint propagation.

Course §2.3.3.1 · What GAC does

Generalized arc consistency (GAC)

GAC requires every remaining value to have support for each rule involving its variable.

The idea: keep values that can work

A value has support if some allowed combination of the other values makes the checked rule true.

The GAC algorithm removes values without support and propagates the effects.

Why “generalized”?

The same test works for different scope sizes:

1 variableX < 2
2 variablesX < Y
3 variablesX + Y = Z

X, Y and Z name variables.

First identify the variable–rule connections. Then define support precisely and use a worklist to schedule the checks.

02 · Reduce the domains

Constraint network: show which rules use which variables

Bipartite graph: two kinds of node

Circle: a variable X.

Rectangle: a constraint c.

Link: X belongs to the scope of c.

A rule using k variables has k links; k is its scope size.

To make domain filtering systematic, record which rules involve each variable. Each network link becomes a support check for GAC.

Mathematical definition · Constraint satisfaction

Constraint network: G = (V, U, E₀)

Two vertex sets

V = 𝓧 = {A,B,C}

V contains the variables.

U = 𝓒 = {c₁,c₂}

c₁ is A<B; c₂ is B<C. U contains the constraints.

Edges join a variable to a rule

E₀ ⊆ V × U
(X,c) ∈ E₀ ⇔ X ∈ scope(c)

V×U means all variable–constraint pairs. E₀ keeps only pairs connected by a scope.

For this chain, E₀={(A,c₁),(B,c₁),(B,c₂),(C,c₂)}. Bipartite means every edge crosses between the two kinds of vertex.

Mathematical definition · Constraint satisfaction

Arc consistency: every value needs a witness

Given a constraint network G and a constraint c with scope(c)={X,Y₁,…,Yₖ}, the edge (X,c) is arc consistent if:

∀ x ∈ dom(X),   ∃ y₁ ∈ dom(Y₁), …, yₖ ∈ dom(Yₖ):
ε({X=x, Y₁=y₁, …, Yₖ=yₖ}, c) = 1x and yᵢ are candidate values; i=1,…,k indexes the k other variables.

Read it in three steps

1 · ∀ x ∈ dom(X)
Take every allowed value of X, one at a time.

2 · ∃ y₁,…,yₖ in their domains
Find one combination of values for the other variables.

3 · ε(assignment, c) = 1
Those values must make rule c true. They are a support, or witness.

Example: c is A < B

Check X=A; the only partner is Y₁=B (k=1). Both domains are {1,2,3,4}.

Value of AOne supporting B
12, since 1 < 2
23, since 2 < 3
34, since 3 < 4
4None → remove A=4

A witness may depend on x. Checking (A,c) and checking (B,c) are separate edge tests.

GAC notation: pending checks and retained values

Use the course’s worklist name E. E₀ is the initial set of all network edges.

E: checks still to perform

E ← E₀

A pair (X,c) means “check variable X against rule c”.

{(A,c), (B,c)} → {(B,c)}

Taking (A,c) removes a pending check, not the rule or network edge.

NX: values kept in this check

NX = {x ∈ dom(X) |
x has support for c}

X is a variable; x is one value. The subscript X identifies the checked variable.

dom(X) ← NX

Replace the domain only if it has shrunk.

02 · Reduce the domains

GAC: pseudocode and its flow

dom is the current domain mapping; E contains pending checks. The variable set 𝓧 and constraint set 𝓒 stay fixed.

01 GAC(dom, E):
02   while E ≠ ∅:
03     take and remove (X,c) from E
04     NX ← {x ∈ dom(X) | x has support for c}
05     if NX ≠ dom(X):
06       dom(X) ← NX
07       if dom(X)=∅: return dom
08       E ← E ∪ {(Z,c′) | c′≠c ∧ Z≠X
09                        ∧ {X,Z}⊆scope(c′)}
10   return dom

Follow the control flow

02–04 · Select and filter

Take one check; compute the values with support.

05–06 · Did anything change?

No: take the next check. Yes: replace the domain.

07–09 · Fail or propagate

Empty domain: return immediately. Otherwise add affected checks to E.

10 · No checks remain

Return the pruned domains.

Start with E=E₀. ∅ means empty; ∪ adds checks. Lines 08–09 revisit another variable Z in another rule c′ that also uses X.

Mathematical definition · Constraint satisfaction

GAC: which checks must be revisited?

After dom(X) shrinks in a check against c, another variable can lose support in another rule.

E ← E ∪ {(Z,c′) | c′≠c ∧ Z≠X ∧ {X,Z} ⊆ scope(c′)}

Read the three filters

c′≠c: consider another rule in 𝓒.

Z≠X: check another variable.

{X,Z}⊆scope(c′): both occur in that rule.

Connect to the chain example

X=B; c is B<CThe domain just revised.
Z=A; c′ is A<BThe check that may be outdated.
Add (A, A<B) to E

Add a check, not a deleted value. ∧ means all three filters must hold; ∪ keeps existing pending checks and adds these pairs.

Read the domains before drawing a conclusion

1 · A domain is empty

dom(X) = ∅∅ is the empty set; X has no possible value.

No solution in this branch.

2 · All domains are singletons

{1}, {2}, {0}Domains of X₁, X₂, X₃, in that order.

After all GAC checks, the one remaining assignment is a solution.

3 · Choices remain

{1}, {1,2}, {0}Domains of X₁, X₂, X₃, in that order.

A solution may or may not exist. More reasoning is needed.

A fixed point means no further pruning. If choices remain, domain splitting creates branches and runs GAC again in each one (Part 2).

02 · Reduce the domains

A partner for each rule is not one shared solution

Separate witnesses can disagree

X₁ = X₂ has the witness (1,1).

X₂ = X₃ has the witness (1,1).

X₁ ≠ X₃ has the witness (1,2).

But: the two equalities force X₁ = X₃, contradicting the inequality.

(X₁=X₂) ∧ (X₂=X₃) ∧ (X₁≠X₃): all three must hold for the same assignment. GAC finds separate witnesses, not one shared solution.
