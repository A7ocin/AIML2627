1 / 34From choices to a solution

A constraint satisfaction problem (CSP) describes choices and the rules those choices must obey. We first build a model, then compare two ways to use it: search through assignments, and propagation through domains.

The running example uses variables X₁, X₂ and X₃, each initially allowed values 0, 1 and 2. Its rules are X₁ < 2, X₂ > 0 and X₃ < X₁. We will use the same example throughout the lecture so that the behavior of each algorithm can be compared directly.

By the end, distinguish a complete solution from a partially assigned context and from a collection of pruned domains. These are different objects, and the algorithms return different kinds of answers.

2 / 34A CSP turns choices into rules

In a timetable model, each course has a variable representing its time slot. The domain lists the slots that the course may use. A constraint between courses that share students or a lecturer prevents simultaneous teaching. Room choices can be modeled with additional variables and capacity or availability rules.

The same modeling pattern applies to robot planning: variables may describe task times or locations, while constraints express precedence, deadlines and reachable locations. In scene understanding, variables can be labels for image regions, with rules describing compatible spatial relationships.

A hard constraint decides whether an assignment is legal. A preference ranks legal assignments, for example by minimizing timetable gaps. Preferences require an objective, weights or a soft-constraint model; they are not automatically equivalent to hard true/false rules.

3 / 34A domain lists a variable’s choices

Original course §2.1 ↗

A variable represents one decision. Its domain is the set of values permitted for that decision. The notation dom(X) names the domain of variable X, and X ∈ dom(X) says that the chosen value must belong to this set. A binary decision might have domain {0,1}; a color choice might have domain {red,green,blue}.

If there are n variables and each has d choices, there are dⁿ total assignments before checking constraints. This follows from choosing a value independently at each position: d × d × … × d, with n factors. For the course example, n=3 and d=3, giving 27 candidates. Ten binary variables give 2¹⁰=1024 candidates.

If the domain sizes differ, multiply the actual sizes. Two variables with three and two choices give 3×2=6 candidates. A compact list of variables and domains may describe a very large search space; the small description does not imply an easy problem.

4 / 34Counting total assignments

Original course §2.1 ↗

Before checking constraints, the assignment space is the Cartesian product of the variable domains: one choice for X₁, one for X₂, and so on. Its size is the product of the domain sizes. This counts candidates, not necessarily solutions.

The symbol ∏ denotes multiplication over an index. In ∏ᵢ₌₁ⁿ |dom(Xᵢ)|, i runs from 1 to n, n is the number of variables, and |dom(Xᵢ)| is the number of values available to Xᵢ. When all sizes equal d, this is dⁿ.

5 / 34An assignment fills in the choices

Original course §2.1 ↗

An atomic assignment gives one variable a value, such as X₁=1. A partial assignment, also called a context, combines such pairs for some of the variables. We use A for a context; the remaining variables have not been decided yet.

A total assignment gives a value to every variable. We use a for a total assignment. The tuple (1,2,0) is shorthand for X₁=1, X₂=2 and X₃=0, in that fixed variable order. A question mark in a teaching diagram represents an unassigned variable; it is not a new value in the domain.

Completeness of an assignment is separate from correctness. The complete tuple (2,1,0) uses allowed domain values but violates X₁ < 2. The tuple (1,2,0) satisfies all three course rules and is a solution.

In the course’s broad definition, a partial assignment may select any subset of variables, including the full set. An assignment with some variables still missing is more specifically a proper partial assignment. Atomic and total assignments are therefore special cases of partial assignments.

6 / 34Restricting an assignment: a[S]

Original course §2.1 ↗

An atomic assignment is one pair X=x, with x∈dom(X). A partial assignment is a collection of such pairs that assigns at most one value to each selected variable. Its selected-variable set is a subset of the problem’s variable set. A total assignment is the special case in which every variable is selected. Thus atomic and total assignments are also partial assignments in the broad mathematical sense.

For an assignment a and a set S of assigned variables, a[S] is the restriction to S: retain exactly the pairs for variables in S. For a={X₁=1,X₂=2,X₃=0} and S={X₁,X₃}, this gives a[S]={X₁=1,X₃=0}. The variable X₂ disappears from the restricted assignment; its original value is not changed.

The course also writes a[X] for the current value of a single variable X. Here a[X₂]=2 is a value, while a[{X₂}]={X₂=2} is a one-pair assignment. The braces distinguish a variable lookup from a restriction to a variable set.

Restriction lets a constraint inspect exactly the variables in its scope. The expression a[scope(c)] will therefore be the input to the evaluation function on the next slides.

a[S] = {X = a[X] | X ∈ S}

Read “the variable–value pairs of a for which X belongs to S”. The vertical bar means “such that”; ∈ means “belongs to”.

a[X₂] = 2    but    a[{X₂}] = {X₂=2}

7 / 34Check a rule when its scope is filled

Original course §2.2 ↗

A constraint has a scope: the set of variables whose values it needs. Unary, binary and ternary constraints use one, two and three variables respectively. The ternary sum on this slide is an illustration of scope; it is not one of the three rules in the running course CSP.

A fully assigned scope allows ordinary true/false evaluation. With X₁=1 and X₂=2, the unary rule X₁ < 2 is true, but X₃ < X₁ is pending because X₃ has no value. If X₃=0 is added, the binary rule is true and X₁+X₂=X₃ is false.

In the reference notation, ε is the evaluation function: it returns 1 for a satisfied constraint and 0 for a violated constraint when all variables in the scope have values. “Pending” is the lab’s label for an incomplete scope, not a third mathematical truth value. Plain backtracking tests complete scopes; stronger propagation may reason about possible values before they are assigned.

For a named rule c, its scope is written scope(c), and its arity is |scope(c)|. The bars |S| denote the size of a set S. For c: X₁+X₂=X₃, scope(c)={X₁,X₂,X₃} and the arity is 3.

8 / 34The evaluation function ε(a, c)

Original course §2.2 ↗

A constraint c is a condition on its scope, the variables it uses. Its arity is |scope(c)|, the number of distinct variables in that scope. Unary, binary and ternary constraints have arities one, two and three.

The evaluation function ε(a,c) returns 1 when the supplied scoped assignment satisfies c, and 0 when it violates c. Its assignment argument must provide all variables in scope(c). If a larger assignment is available, first restrict it and write ε(a[scope(c)],c). We consistently place the assignment first and the constraint second.

For c given by X₃<X₁, the pair {X₁=1,X₃=0} evaluates to 1, whereas {X₁=0,X₃=1} evaluates to 0. With only X₁ assigned, this evaluation cannot yet be performed: X₃ is missing.

The lab describes an incomplete scope as pending. That is a statement about whether we have enough input, not a third numerical output of ε. In particular, an incomplete assignment must not automatically receive evaluation 0.

ε(a,c) ∈ {0,1}
ε(a[scope(c)],c)

First select the values used by c; then test c on those values.

9 / 34Combining conditions: ∧ means AND, ∨ means OR

Original course §2.2 ↗

Logical connectives combine statements into a larger condition. The symbol ∧ means AND, also called conjunction: the combined condition is true only if every part is true. The symbol ∨ means OR, also called disjunction: the combined condition is true if at least one part is true. This OR is inclusive, so it is also true when both parts are true.

The course CSP has variables X₁,X₂,X₃ with domains {0,1,2}. Its three constraints must hold together: (X₁ < 2) ∧ (X₂ > 0) ∧ (X₃ < X₁). Parentheses group the individual statements; ∧ connects them. Writing the constraints as a comma-separated set or list is shorthand for requiring all of them, rather than choosing just one.

Take the total assignment (1,0,0), in order X₁,X₂,X₃. The three course rules give true, false, true. Their conjunction is therefore false: this candidate is not a solution, even though two rules hold.

For a separate OR illustration, consider (X₁=1) ∨ (X₂=2). At (1,0,0), the left statement is true and the right is false, so the OR is true. At (1,2,0), both are true and the OR is still true. At (0,0,0), both are false and the OR is false. This example is not an additional constraint in the course CSP; satisfying it alone does not establish a course solution.

A CSP takes the conjunction of all its constraints. Within one constraint, AND and OR may be combined to describe the permitted alternatives. For example, the course solutions can be written as (X₁=1) ∧ ((X₂=1) ∨ (X₂=2)) ∧ (X₃=0). The outer AND fixes X₁ and X₃; the grouped OR permits either remaining X₂ value. Without parentheses, AND is conventionally read before OR; explicit grouping makes the intended rule easier to see.

The truth table uses r and s to stand for statements, not CSP variables. It assumes their inputs are available so each statement has a true/false value. With a partial context, a rule whose scope is incomplete remains pending, as in the evaluation examples. The logical symbols do not turn a missing value into false.

Do not confuse ∧ and ∨, which combine statements, with ∩ and ∪, which combine sets. For example, X₂∈{1,2} describes a choice from a set and is equivalent to (X₂=1) ∨ (X₂=2); it does not assign the set {1,2} as X₂’s value.

10 / 34Formal definition of a CSP

Original course §2.3 ↗

A constraint satisfaction problem is the tuple P=(𝓧,dom,𝓒). The set 𝓧={X₁,…,Xₙ} contains n variables. The function dom associates each variable X with an allowed-value set dom(X). The set 𝓒={c₁,…,cₘ} contains m constraints. The indices i and j can select a variable Xᵢ or a constraint cⱼ.

The notation X↦dom(X) describes the domain function’s action. dom is the mapping; dom(X) is one set returned by it. For example, dom(X₁)={0,1,2}. A constraint’s scope must contain only problem variables: scope(c)⊆𝓧.

A candidate assignment must use legal domain values. Being total only says that all variables have values; it does not yet say that those values satisfy the constraints. The formal solution test adds that second requirement.

These packs use finite domains when claiming exhaustive termination or enumerating all solutions. A model may otherwise admit infinite domains, for which the finite search guarantees do not automatically apply.

11 / 34The running CSP has exactly two solutions

Original course §2.3 ↗

We write P=(𝓧,dom,𝓒). P names the whole problem, 𝓧 is its set of variables, dom associates each variable with its allowed values, and 𝓒 is its set of constraints. In dom(Xᵢ), i is a variable index: here i is 1, 2 or 3.

The course problem uses 𝓧={X₁,X₂,X₃}, dom(Xᵢ)={0,1,2}, and three constraints: X₁ < 2, X₂ > 0 and X₃ < X₁. A solution must choose domain values and satisfy every constraint at once.

The first rule restricts X₁ to 0 or 1. If X₁=0, no allowed X₃ is smaller. Therefore X₁=1 and X₃=0. The second rule leaves X₂=1 or X₂=2. The two solutions are consequently (1,1,0) and (1,2,0). We can either find one solution or enumerate all solutions; the stopping rule must match that goal.

Written as one condition, the three course constraints are (X₁ < 2) ∧ (X₂ > 0) ∧ (X₃ < X₁). Their AND requires all three. Equivalently, the complete solution set is described by (X₁=1) ∧ ((X₂=1) ∨ (X₂=2)) ∧ (X₃=0): X₁ is 1, X₃ is 0, and X₂ may be 1 or 2. The OR is inside the X₂ alternatives; it does not replace the AND across constraints.

12 / 34The mathematical test for a solution

Original course §2.3 ↗

A CSP solution is a total assignment a that uses a value from dom(X) for every X∈𝓧 and satisfies every c∈𝓒. The universal quantifier ∀ expresses “for every”; the membership sign ∈ expresses “belongs to”.

To read the formula, take each constraint c in turn. Compute scope(c), retain the corresponding pairs a[scope(c)], and evaluate ε on those pairs and c. Every result must be 1. The rule is an AND (∧) over the constraint set: all evaluations must be 1. It is not an OR (∨), which would only require one of them to be 1.

For the course candidate (1,1,0), the three evaluations are 1,1,1, so it is a solution. The tuple (2,1,0) uses allowed domain values but gives 0 for X₁<2, so it is not a solution even though its other two evaluations are 1.

The domain check is a separate premise. A tuple using an out-of-domain value is not a valid candidate even if some constraints happen to hold. Finding one such legal, all-ones assignment proves that the CSP is satisfiable; finding every one requires further exploration.

13 / 34Generate-and-test: the naive solution

Original course §2.3 ↗

Begin with X₁=1 and the other two variables unassigned. X₁ < 2 is true. X₂ > 0 and X₃ < X₁ are pending because their scopes are incomplete. Pending does not mean violated.

14 / 34Generate a candidate, then test every rule

Original course §2.3.1 ↗

Generate-and-test enumerates total assignments and evaluates all constraints for each one. A candidate is a solution only when every rule holds. To find all solutions, continue through the entire Cartesian product of domains. To find one solution, stop on the first success.

This method is simple and complete for finite domains, but it can do unnecessary work. With fifteen variables and four choices each, there are over one billion candidates before applying the rules.

In the course example, all nine assignments beginning with X₁=2 fail the same unary rule. Generate-and-test may complete and reject them separately. Backtracking can recognize that failure once and discard the whole branch.

15 / 34Backtracking cuts a branch as soon as it fails

Original course §2.3.2 ↗

Backtracking explores a tree of partial assignments. The root is the empty context; each edge adds one variable–value pair. A node is rejected as soon as a constraint with a complete scope is false. Descendants inherit that violation, so none can be a solution.

For X₁=2, the rule X₁ < 2 is immediately false, and the nine combinations of X₂ and X₃ are skipped. For X₁=0, the unary rule is true and X₃ < X₁ is pending. Plain backtracking continues until X₃ receives a value, at which point every allowed value fails. Propagation can detect this impossibility earlier.

Undoing a choice restores the previous context so another value can be tried. Depth-first search follows one branch at a time and then returns to alternatives. If all branches of a finite problem are explored, backtracking finds all solutions or proves there are none.

16 / 34Which constraints can a context evaluate?

Original course §2.3.2 ↗

The DFS solver maintains a partial assignment A called the context. Write vars(A) for the variables that already have values. For example, A={X₁=1,X₃=0} has vars(A)={X₁,X₃}.

The course’s notation c≡A means that c can be evaluated in A. Formally, scope(c)⊆vars(A). The subset relation ⊆ allows equality: having exactly the needed variables is enough. This use of ≡ denotes evaluability, not truth, logical equivalence or equality of the two objects.

In a separate illustrative rule c: X₁=X₃, the context {X₁=1,X₃=0} supplies the whole scope, so c≡A holds; the rule itself is false and ε(A[scope(c)],c)=0. A rule using the unassigned X₂ is not evaluable in that context.

The eligible set 𝓒ₑ={c∈𝓒 | c≡A} collects all rules that can currently be tested. DFS first rejects the context if any of those evaluations is 0. If all are 1, their truth cannot be undone by assigning previously unassigned variables, so the recursive call may omit those checked rules.

19 / 34Choose the next decision to reduce wasted work

Original course §2.3.2 ↗

Variable ordering chooses which unassigned variable to consider next. 20 / 34Consistency algorithms: filter before branching

Original course §2.3.3 ↗

DFS can be inefficient in some cases because it may rediscover the same failure for several choices of another variable. This motivates the transition in the original course’s §2.3.3: rather than waiting for each complete rule scope to be assigned, reason about which values still have any chance of satisfying the rule.

Consider two variables A and B with dom(A)=dom(B)={1,2,3,4} and the constraint A<B. These rename the original section’s X₁ and X₂. Suppose ordinary DFS assigns A first and chooses A=4. Because B is still unassigned, this binary rule is not yet evaluable in the context. DFS then tries B=1, B=2, B=3 and B=4. The corresponding tests 4<1, 4<2, 4<3 and 4<4 all fail, so it rejects four completions of the same hopeless A choice.

A consistency algorithm reasons over the domains instead: is there any allowed B greater than 4? There is none, so 4 can be removed from dom(A) before branching on A. This single filtering step excludes every completion with A=4. It is safe because no solution could have used that value. The next slide also considers the other direction: B=1 has no smaller allowed A and can be deleted from dom(B).

More generally, consistency algorithms shrink domains by enforcing a stated local consistency property. A sound deletion removes a value only when it cannot participate in any satisfying combination for the checked constraint, thereby preserving every solution. The output is usually smaller domains, rather than a set of complete solution assignments. This adds reasoning to ordinary DFS; methods that already combine search with propagation perform such checks during search.

Constraint propagation repeats these deductions as domains change. Deleting a value can remove a partner needed by another variable, making an earlier check outdated. The propagation algorithm schedules the affected checks again. A consistency property describes what must hold; a consistency algorithm describes how to enforce it.

The following examples first make filtering visible, then introduce the constraint network, support, arc consistency and the generalized arc consistency (GAC) worklist. Unary consistency checks one variable’s values; binary arc consistency checks partner values; GAC handles constraints of any scope size. Here an arc is a variable–constraint pair. Because these are local checks, nonempty filtered domains need not establish that one assignment satisfies all constraints together. Part 2 adds domain splitting to explore unresolved choices systematically.

22 / 34Generalized arc consistency (GAC)

Original course §2.3.3.1 ↗

Generalized arc consistency (GAC) is the support requirement enforced by the GAC filtering algorithm. 32 / 34Read the domains before drawing a conclusion

Original course §2.3.3.1 ↗

An empty domain means no value for that variable can be part of a solution under the current branch restrictions. Because GAC removes only unsupported values, the branch can be rejected. If this occurs at the root, the whole CSP has no solution.

If every domain contains exactly one value and all constraints are GAC-consistent, those values determine a solution. Each constraint’s only possible scoped tuple must satisfy it; otherwise a value would have no support.

If the domains are all nonempty but at least one has several values, GAC alone is inconclusive. The course example’s domains {1}, {1,2}, {0} lead to two solutions, while the next example has no solution despite nonempty domains.

A fixed point describes the end of propagation, not the end of the entire search. Domain splitting in Part 2 turns remaining alternatives into separate branches and applies propagation to each.

33 / 34A partner for each rule is not one shared solution

Original course §2.3.3.1 ↗

All three variables have domain {1,2,3,4}. The constraints are X₁=X₂, X₂=X₃ and X₁≠X₃. Each value has an equal partner for an equality, and a different partner for the inequality, so GAC removes nothing.

The witnesses are independent. For example, (X₁,X₂)=(1,1) satisfies the first rule, (X₂,X₃)=(1,1) satisfies the second, and (X₁,X₃)=(1,2) satisfies the third. These separate pairs are not one consistent assignment: they give different requirements for X₃.

Globally, the two equalities imply X₁=X₃. The inequality demands the opposite, so no solution exists. This counterexample proves that nonempty GAC-consistent domains do not generally establish satisfiability.

Local consistency checks only scoped supports. Search or stronger consistency reasoning is needed when those local choices must be made compatible across several constraints.

The combined requirement is (X₁=X₂) ∧ (X₂=X₃) ∧ (X₁≠X₃). The conjunction symbol ∧ requires one shared total assignment to satisfy all three statements. Independent witnesses for individual constraints do not make their conjunction satisfiable.

Current slide · supporting points and links

Separate witnesses can disagree

X₁ = X₂ has the witness (1,1).

X₂ = X₃ has the witness (1,1).

X₁ ≠ X₃ has the witness (1,2).

But: the two equalities force X₁ = X₃, contradicting the inequality.

(X₁=X₂) ∧ (X₂=X₃) ∧ (X₁≠X₃): all three must hold for the same assignment. GAC finds separate witnesses, not one shared solution.
