5.1 · From the observations to a model

Why not fit a line or polynomial?

Polynomial degrees
Fit the same 100 patients with different polynomial degrees.
Ordinary regression can leave the range [0,1], so its outputs are not automatically valid class probabilities.
The observations occupy two levels because the outcome is either zero or one. In this particular teaching sample, the transition between those levels is sharp. A familiar first attempt is to fit a regression line or polynomial to the numerical codes and then round or threshold its output. The purple line is an actual ordinary-least-squares fit to the same one hundred observations. It gives some predictions below zero and above one, so those values cannot be interpreted directly as probabilities. A higher-order polynomial can follow a steep pattern more closely, but it does not automatically enforce valid probabilities either. Regression on binary labels is possible; the point is that we want an explicit, interpretable model of the probabilities of the classes. We will therefore estimate P(Y=0|X=x) and P(Y=1|X=x), and subsequently turn those estimates into a label. This motivates the probabilistic framework introduced after the formal description of the classification task. 5.2 · Probabilistic interpretation of machine learning

Two types of uncertainty

Epistemic:

Uncertainty in the measurements that can be controlled, to a certain extent.

Better tools or additional predictors can decrease epistemic uncertainty.

Aleatoric:

Uncertainty intrinsic in the process that cannot be controlled and therefore not decreased.

We can know these probabilities and still be uncertain about the next outcome.

The distinction depends on the context and on what we measure.
Epistemic: uncertainty in the measurements that can be controlled, to a certain extent. In a predictor, we can adopt more accurate measurement tools. In an outcome, we can also include more predictors. Epistemic uncertainty can be decreased. Aleatoric: uncertainty intrinsic in the process that cannot be controlled and therefore not decreased. The distinction is labile and depends on the context in which we conduct experiments. What can be controlled depends on the measurement setup and available inputs. Lowercase p names the conditional probability mass function (PMF) of Y given X.
Because Y has discrete class labels, this function assigns a probability to each possible class.
For example, p(1 | 0.50) = 0.70. The event notation ℙ(Y=1 | X=0.50) gives the same probability.

Lowercase p names the conditional probability mass function (PMF) of the discrete class variable Y given input X. A mass function assigns a probability to each possible class. At a fixed input x, its values are nonnegative and sum to one across the classes. Evaluating p(y|x) gives the probability of class y at input x. The full function name is p_{Y|X}; p(y|x) drops the variable subscripts when clear. The probability operator ℙ instead takes an event: ℙ(Y=y|X=x). The two expressions have the same value. In the example the conditional PMF assigns 0.30 to class 0 and 0.70 to class 1 at input 0.50. The name mass function refers to the discrete outcome Y, even when the input X is continuous.
5.2.1 · Why use class probabilities?

Why predict probabilities before choosing a class?

1. A smoother learning signal

0.60 ⟶ 0.80

Probabilities change continuously. Often, optimizing them is simpler than optimizing discrete class labels.

If the observed class is 1, 0.60 to 0.80 strengthens the prediction while its label stays 1.

2. A measure of model confidence

Concentrated probabilities express more confidence. Similar probabilities express less.
A confident prediction can still be wrong.
Probabilities offer the two advantages in the classification argument: a continuous quantity to optimize, and an expression of confidence. A peaked distribution puts most mass on a single class. A flat distribution gives similar probabilities to the possible classes. Confidence can be mistaken.
5.3 · Optimal Bayes classifier

If we knew the true probabilities, which label should we choose?

The Optimal Bayes Classifier (OBC) chooses the most probable class. It is a theoretical benchmark: in practice we usually have to estimate those probabilities.

Example: 70% present, 30% absent

Choose class 1.
It is the label with the higher chance of being right.

What does “optimal” mean here?

The lowest expected fraction of wrong labels, using these features and treating every mistake as equally costly.

𝒴 = {0,1}, the class setxᵢ = input for observation iŷᵢ = predicted labelf = Optimal Bayes ClassifierAt exactly 50%, either label has the same expected error. This rule chooses 1.
The OBC assumes that we know the true conditional relationship ℙ(Y|X). Usually we do not, so it is a theoretical baseline. It chooses the most probable label to minimize the expected number of mistakes, counting each wrong label equally.

5.3 · Measuring classification mistakes

The error rate is the probability that our label is wrong

Even the most likely class can be wrong. To compare classifiers, we average their mistakes over possible inputs and outcomes.

R(f)=𝔼XY[𝟙(Y≠f(X))]

𝟙 is called an indicator function

𝟙(Y≠f(X))={1wrong label0correct label

The expectation averages those 0s and 1s

Toy population: 10 equally likely cases

0100100010
R(f)=3 wrong10 cases=0.30

0 = correct label1 = wrong label

R(f) is called risk or expected classification error. It lies between 0 and 1.
We will show that the Bayes rule gives the smallest possible R(f) for these features.
f = any classifierf(X) = predicted labelY = outcomeX = input𝟙(…) = 1 when the condition is true, otherwise 0𝔼ₓᵧ = average over X and Y
Risk here means expected classification error under 0–1 loss. It is not an unspecified measure of harm. For each possible observation, the indicator contributes one if the prediction differs from the outcome and zero otherwise. The average of this zero-or-one variable is the probability of an error. The expectation averages with respect to the population distribution of both X and Y, so common observations receive greater weight than rare ones. Exact population risk is usually unknown. The fraction of wrong predictions in representative held-out observations estimates it. The next two slides first compare the two possible predictions at one fixed input and then prove that making the better choice at every input minimizes the population average. The example uses a toy population of ten equally likely possible cases. Each contributes an indicator: one for an error, zero for a correct prediction. Three of the ten cases have an error, so the expectation of the indicator is 3/10=0.30. For a finite evaluation sample rather than the full population, the same average would estimate the unknown population risk.

Which class gives the smaller chance of a mistake?

Reminder: the OBC chooses the class with the highest true probability. The individual case’s label is still unknown.

Here p(x) always means the probability of class 1. The class 1 is understood in this shorter notation.

y^=argmaxc∈𝒴 ℙ(Y=c∣X=x)
X = random input, x = one fixed input valueY = actual class, 𝒴 = {0,1} = possible class labelsŷ = predicted label, c = candidate class from 𝒴p(X) = the same class-1 probability function evaluated at the random input X
We return to a binary problem with class labels {0,1}. Fix one particular input x. We compare two decisions for that same input: predicting 0 and predicting 1. On these proof slides, p(x) is shorthand for p(1 | x)=ℙ(Y=1 | X=x). The class 1 is already fixed in its definition, so it is left out of the arguments. The other class has probability 1−p(x), because the two possible class probabilities add up to one. Suppose p(x)=0.70. Class 1 then has probability 70%, and class 0 has probability 30%. If we predict 0, we are wrong whenever the outcome is 1: a 70% chance of a mistake. If we predict 1, we are wrong whenever the outcome is 0: a 30% chance. We choose 1 because 30% is smaller than 70%. These are probabilities, so an individual prediction can still be wrong. More generally, predicting 0 has error probability p(x), and predicting 1 has error probability 1−p(x). Choose the smaller of these two errors at each input. Minimizing the error separately at every input also minimizes their overall average, which the next slide derives. Lowercase x is a fixed input value, so p(x) is a number for that input. Uppercase X is a random input, so p(X) varies with whichever input occurs. Once X=x is observed, p(X) takes the value p(x). The next derivation uses p(X) while averaging over inputs. In both forms p still denotes the class-1 probability, rather than the input density p_X(x) introduced later. Reminder: the OBC always chooses a class attaining the highest true conditional probability at the given input. It assumes these probabilities are known, while the individual outcome is still unknown. The argmax formula returns the class label, not the probability value. Here class 1 has probability 0.70 and therefore gives the smallest error probability, 0.30.

Naive Bayes uses Bayes’ theorem to estimate the posterior. The word equation and the symbolic equation are the same identity. Subscripts identify distributions: p_Y for class, p_X for input and p_X|Y for input given class. The notation p_Y|X(y|x) is the conditional class probability ℙ(Y=y|X=x). When X is continuous, the likelihood and evidence are densities, not probabilities of a single exact input. In the weather example, X records cloud condition and Y records rain status. The posterior is the probability of rain given that it is cloudy. The likelihood reverses the conditioning: probability of cloudy skies given rain. The prior is the overall probability of rain before considering the cloud condition. The evidence is the overall probability of cloudy skies, across rainy and dry cases.

5.5 · Estimating the distributions

The “naive” assumption makes the likelihood simpler

Let x=(x1,…,xm). We leave out the observation index i to focus on one input.

Assume the predictors are conditionally independent given the class.
Under this assumption, model each feature separately within class c, then multiply. These are easier, one-variable distributions.
Xⱼ = random variable for feature jxⱼ = its value in this inputm = number of featuresj = feature index, from 1 to mc ∈ 𝒴 = a candidate class∏ = multiply one term per feature
The first equality only unpacks the feature vector. The second equality uses the Naive Bayes assumption of conditional independence given the class. Without that assumption, the joint likelihood need not factor. The third equality rewrites the long product using product notation. Each feature distribution is univariate, meaning it describes one variable. The predictors need not be independent when different classes are mixed together.

Why can we use log scores and omit the evidence?

01 · Start from the Bayes decision

5.6 · Logistic regression

Can we predict the class probability directly?

Naive Bayes

First model the feature values within each class.

Estimate how the features are distributed for each class c and how common that class is (its prior).

Then use Bayes’ theorem to compute the probability of class c for the observed input xᵢ:

pY∣X(c∣xi)=pX∣Y(xi∣c)pY(c)pX(xi)

This combines the feature likelihood, class prior and evidence.

Logistic regression

Model the probability of a class directly from the feature values.

For input xᵢ, calculate a weighted sum of its features: a linear score.

An S-shaped logistic function converts that score into a probability between 0 and 1:

ℙ(Y=1∣X=xi)=σ(xi)

The coefficients are learned from labelled examples. The next slide gives the formula for σ(xᵢ).

X = input features, xᵢ = their values for observation iY = class variable, c = a candidate class labelσ(xᵢ) = logistic model’s probability of class 1p = probability or density function identified by its subscript
The arrows previously meant “use these quantities to compute the class probability”. The slide now writes the operations explicitly. Naive Bayes estimates feature distributions within each class and the class priors, then applies Bayes’ theorem. Logistic regression directly specifies the class-1 probability as a function of the observed input, using a weighted linear score and logistic transformation. Its coefficients are learned from labelled training data. Both methods produce class probabilities, from which a class label can be selected. The next slide spells out the logistic formula using the same notation.

Set xᵢ₀=1 to include the intercept β₀.

The two fractions are equal: multiply the first numerator and denominator by e∑j=0mβjxij.
i = observation indexj = feature index, m = number of featuresxᵢⱼ = feature j for observation iβⱼ = learnable coefficient, β₀ = intercepte ≈ 2.718 = exponential baseσ(xᵢ) = logistic function evaluated using input xᵢ
The full probability formula uses the notation used here σ(x_i), combining the linear score and logistic transformation. The j=0 term is the intercept because x_i0=1. The equivalent positive-exponential fraction follows by multiplying numerator and denominator by exp(sum beta_j x_ij). The learnable coefficients keep the familiar linear-score form but are inside an exponential, so the probability is nonlinear in the coefficients. For finite scores it is strictly between zero and one. There is no additive error term on the categorical label; uncertainty is intrinsic in the class probabilities.

5.6.1 · Maximum likelihood estimation

A good probability model makes the observed labels plausible

Why multiply? We want the probability of both recorded labels occurring together. Given the inputs, the model treats the two patients’ labels as independent, so it multiplies the probability it assigns to each recorded label (slide 25).

Two fixed labels: y₁ = 1, y₂ = 0Model AModel B
Model’s class-1 probabilities(0.9, 0.9)(0.6, 0.4)
Patient 1 has label 1: use σ(x₁)0.90.6
Patient 2 has label 0: use 1−σ(x₂)1−0.9 = 0.11−0.4 = 0.6
Joint likelihood: σ(x₁) × (1 − σ(x₂))0.9 × 0.1 = 0.090.6 × 0.6 = 0.36
Model B assigns four times the likelihood to the observed pair (0.36 / 0.09).
Model A gives only 0.10 to patient 2’s recorded label.
Hold both inputs fixed. For patient 1, the recorded label is 1, so the model assigns it probability σ(x₁). For patient 2, the recorded label is 0, so its probability is 1 − σ(x₂). The model assumes the two labels are independent given their inputs. The probability of observing both labels in that order is therefore σ(x₁) × (1 − σ(x₂)). We call this product the likelihood for the candidate model. For model A the product is 0.9×0.1=0.09. For model B it is 0.6×0.6=0.36. Model B assigns four times as much likelihood to the observed pair, even though model A is more confident about its second, incorrect label. This is a concrete example of the two-product MLE formula.
5.6.1 · Maximum likelihood estimation

Choose coefficients that make the observed labels likely

𝛃^=argmax𝛃∈ℝm+1 ∏i:yi=1σ(xi)∏i′:yi′=0(1−σ(xi′))

If the recorded label is 1

Use the factor σ(xi)

This is the probability assigned to what actually happened.

Example: σ(xᵢ)=0.8 gives a factor of 0.8. Increasing it toward 1 makes the observed label more likely.

If the recorded label is 0

Use the factor 1−σ(xi′)

Use the probability of class 0, because that is what happened.

Example: σ(xᵢ′)=0.2 gives 1−0.2=0.8. Moving σ(xᵢ′) toward 0 increases this factor.

The same coefficients determine every probability in the product.
Maximum Likelihood Estimation (MLE) chooses the coefficients with the largest joint likelihood. argmax returns those coefficients, rather than the product value.
𝛃=(β₀,…,βₘ) = coefficients, β₀ is the intercept𝛃^ = the fitted coefficient vectorm = number of features
ℝm+1 = m feature coefficients + 1 intercept∏ = multiply all indicated observationsi,i′ = observation indices, yᵢ,yᵢ′ = their observed labelsσ(x) = class-1 probability for candidate 𝛃
Maximum Likelihood Estimation (MLE) chooses coefficients that maximize the likelihood of the observed data. Inputs and labels stay fixed while we compare candidate coefficient vectors 𝛃=(β₀,…,βₘ). The vector belongs to ℝᵐ⁺¹ because it contains m feature coefficients and an intercept. For each observation with yᵢ=1, the probability assigned to the observed label is σ(xᵢ). For each observation with yᵢ′=0, that probability is 1−σ(xᵢ′). The two products include the two label groups, with i and i′ serving as observation indices. Assuming independent observations under the model, multiply all their contributions. The factors depend on 𝛃 through the logistic function. Maximizing the product encourages σ(xᵢ) toward 1 for positive labels and toward 0 for negative labels. We write argmax because the output β̂ is a vector of coefficients, not the maximum likelihood value itself.
5.6.1 · Maximum likelihood estimation

How do we find those coefficients?

1. Try coefficients

Start with a candidate 𝛃.
Use the logistic formula to compute σ(xᵢ) for every training input.

2. Calculate the likelihood

For each label 1 use σ(xᵢ).
For each label 0 use 1−σ(xᵢ).
Multiply those contributions.

3. Improve the candidate

A numerical optimizer adjusts the coefficients to seek a larger likelihood.
Repeat until its stopping criterion is met.

This problem has no closed-form coefficient formula like ordinary least squares.
We use numerical optimization: improve candidate coefficients through calculations.
𝛃 = coefficients currently being triedσ(xᵢ) = probability computed from those coefficients𝛃^ = resulting fitted coefficientsNumerical optimization = repeated calculations to improve candidate coefficients
The likelihood objective tells us which coefficients we want, but it does not provide a closed-form solution. Unlike the ordinary least-squares formula seen in regression, logistic regression generally requires numerical optimization. Conceptually, try a coefficient vector, compute the class probabilities and their likelihood, then adjust the vector to seek a larger likelihood. A numerical routine repeats calculations until its stopping rule is met. This description explains the role of the optimizer without introducing a separate optimization algorithm.
