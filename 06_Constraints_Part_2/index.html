Part 1 recap · 1 of 6

A CSP describes choices and rules

CSP means constraint satisfaction problem. We want to choose values that obey every rule.

Variables: what we choose

X₁, X₂, X₃

Three named choices. Each variable will receive one number.

Domains: allowed choices

{0,1,2}

Each variable starts with these options. dom(X) means “the domain of X”.

Constraints: the rules

(X₁ < 2)
∧ (X₂ > 0)
∧ (X₃ < X₁)

∧ means AND: a solution must satisfy all three rules.

Capital X names a variable; lowercase x can name one of its values. Braces {…} enclose a set of available options.

Part 1 recap · 2 of 6

Combining conditions: ∧ means AND, ∨ means OR

A connective combines true/false statements. Here each X₁, X₂, X₃ has domain {0,1,2}.

∧ · AND: all conditions must hold

(X₁ < 2) ∧ (X₂ > 0)
∧ (X₃ < X₁)

This is the running CSP: satisfy all three rules together.

(1,0,0): false overall.
The middle rule fails; the others hold.

∨ · OR: at least one must hold

(X₁ = 1) ∨ (X₂ = 2)

An illustrative OR constraint.
Either part may hold; both may hold too.

(1,0,0): true overall.
The left part holds, so this OR holds.

A CSP requires an AND across its constraints. An individual constraint may contain OR. The OR example is a separate illustration, not an extra rule in the running CSP.

Having values is different from having a solution

An assignment chooses values. A solution is a total assignment that satisfies every constraint.

Partial: choices are missing

X₁1
X₂?
X₃?

A={X₁=1} is a partial context. X₂ and X₃ are unassigned.

X₁<2 is true; the other rules are pending.

Total and valid: a solution

X₁1
X₂2
X₃0

Every variable has a value, and every rule holds:

(1<2) ∧ (2>0) ∧ (0<1): true.

Total but invalid: not a solution

X₁0
X₂1
X₃0

All values are allowed, but X₃<X₁ becomes 0<0, which is false.

We write a total assignment as a tuple, such as (1,2,0), in the fixed order X₁, X₂, X₃. “?” means unassigned; it is not a domain value.

Part 1 recap · 5 of 6

Recap: generalized arc consistency (GAC)

GAC filters domains: remove a value when it has no satisfying partners for a rule. Example: X₃ < X₁, both domains {0,1,2}.

X₁ = 1 has a partner

X₃ = 0 → 0 < 1

This satisfying pair is a support, also called a witness. Keep X₁=1 for this rule.

X₁ = 0 has no partner

0, 1, 2: none is below 0

No possible X₃ makes the rule true. Remove X₁=0 from its domain.

After a deletion, affected checks return to the worklist E. Repeat until E is empty or a domain is empty.

After GAC, one choice is still open

VariableInitial domainAfter GAC
X₁{0,1,2}{1}
X₂{0,1,2}{1,2}
X₃{0,1,2}{0}

What is settled here?

X₁=1 ∧ X₃=0 are fixed. X₂=1 ∨ X₂=2 is still a choice.

What comes next?

Try the X₂ alternatives in separate branches. Propagate again inside each branch.

In general: an empty domain means failure; all singleton domains after GAC give a solution; remaining choices leave the result unresolved. A singleton is a set with one value.

Constraint satisfaction · Part 2 · Reconnect before continuing

Two ways to continue after propagation

Domain splitting

Split a remaining domain. Propagate each branch and explore all alternatives.

domains → branches → solutions

Local search

Change one value at a time. Reduce conflicts, and sometimes move sideways or uphill.

candidate → moves → no conflicts

Systematic search can prove impossibility when exhaustive. A bounded local-search run may simply finish without finding a solution.

02 · Search after propagation

Split the choices, then propagate each branch

After GAC: (X₁=1) ∧ ((X₂=1) ∨ (X₂=2)) ∧ (X₃=0). Split the OR into two branches; keep every original constraint in both.

The parts must be nonempty, disjoint and cover the original domain. Copy the domains, run GAC in each branch, and explore both.

Mathematical definition · Constraint satisfaction

A split is a partition of one domain

Keep every choice exactly once

D₁ ∪ D₂ = dom₀(X)
(D₁ ∩ D₂ = ∅)
∧ (D₁≠∅) ∧ (D₂≠∅)

dom₀ is the domain mapping after GAC; D₁ and D₂ are the two parts.

Make independent branch mappings

VariableBranch j, with j=1 or 2
The selected Xdomⱼ(X)=Dⱼ
Any other Y≠Xdomⱼ(Y)=dom₀(Y)

Example: {1,2,3,4} splits into {1,2} and {3,4}.

∪ = union; ∩ = intersection; ∅ = empty set; ∧ = AND. All conditions must hold: the parts cover the domain, do not overlap, and are nonempty.

Mathematical definition · Constraint satisfaction

Consistency solver: propagate, then recurse

Input: variables 𝓧 with their domains, constraints 𝓒, and pending checks E. Result: a set of solutions.

procedure Con_Solve(𝓧, 𝓒, E)// Inputs: variables, constraints and checks.
dom₀ = GAC(𝓧, 𝓒, E)// Filter the current domains using GAC.
if ∃X∈𝓧, dom₀(X)=∅ then// Does any variable have no value left?
return ∅// Reject this branch: it has no solution.
else if ∀X∈𝓧, |dom₀(X)|=1 then// Does every variable have exactly one value?
return {{X=x | X∈𝓧, x∈dom₀(X)}}// Return a set containing that one assignment.
else// Some domains still contain choices.
select X such that |dom₀(X)|>1// Choose one variable that needs a decision.
partition dom₀(X) into D₁ and D₂// Two nonempty, disjoint parts cover its values.
(∀Y≠X, dom₁(Y)=dom₀(Y)) ∧ dom₁(X)=D₁// Branch 1: copy other domains; restrict X to D₁.
(∀Y≠X, dom₂(Y)=dom₀(Y)) ∧ dom₂(X)=D₂// Branch 2: copy other domains; restrict X to D₂.
E′ = {(Z,c′) | Z≠X, {X,Z}⊆scope(c′)}// Recheck other variables in rules involving X.
return Con_Solve(𝓧[dom₁],𝓒,E′) ∪ Con_Solve(𝓧[dom₂],𝓒,E′)// Solve both branches; combine their solutions.
end if// All three cases have now been handled.
end procedure// End the procedure.

𝓧: variables with current domains.
𝓒: constraints · X,Y,Z: variables.
x: a value · D₁,D₂: the two parts.

dom₀: after GAC · dom₁,dom₂: branch domains.
domⱼ(X): X’s values in branch j (1 or 2).
𝓧[domⱼ]: same variables, using domains domⱼ.

E: pending (variable,rule) checks.
E′: affected checks · c′: a constraint.
scope(c′): variables used by that constraint.

∃: some · ∀: every · ∈: belongs to · ⊆: subset · ∧: AND · ∪: union · ∅: empty set · |…|: number of values.

{… | …}: items meeting all the conditions · {{…}}: a set containing one assignment. “=” stores a result on lines 2, 10–12; tests compare values.

From systematic search to local search

Why move from systematic to local search?

The assignment space is the set of possible combinations of variable values.

So far: explore branches

Explore alternatives systematically, pruning impossible branches.

A huge space can be too costly to finish; an infinite space may never be exhausted.

Next: make local changes

Keep one complete candidate and change it a little at a time.

Visit selected candidates, without trying to cover every alternative.

The trade-off: local search can find a solution with less work, but may miss one even when it exists.

Our examples have finite domains. Infinite domains can create infinitely many assignments.

Generic search

General local search: read the algorithm

Input: variables 𝓧 and constraints 𝓒. Goal: a complete assignment that satisfies every constraint.

procedure Local_search(𝓧, 𝓒)// Inputs: variables 𝓧 and constraints 𝓒.
repeat// Begin an attempt; restart here if needed.
for X ∈ 𝓧 do// Visit every variable X.
a[X] = rand(dom(X))// Give X a random allowed value.
end for// a now assigns a value to every variable.
while ¬stop() ∧ ∃c∈𝓒, ε(a[scope(c)],c)=0 do// Continue if not stopped AND a rule fails.
Y = select_var(𝓧)// Choose the variable Y to update.
y = select_val(dom(Y))// Choose its allowed replacement value y.
a[Y] = y// Change only Y’s value in candidate a.
end while// Return to the test on line 6.
if ∀c∈𝓒, ε(a[scope(c)],c)=1 then// Check whether EVERY constraint holds.
return a// Success: return this complete solution.
end if// If the test failed, continue to line 14.
until terminate()// Finish overall, or begin another attempt.
return ∅// This run found no solution; not a proof of none.
end procedure// End the procedure.

𝓧: variables · 𝓒: constraints.
X,Y: variables · y: a value.
a: complete candidate; a[Y]: Y’s value.

dom(Y): allowed values of Y.
scope(c): variables used by rule c.
ε(a[scope(c)],c): 1 if c holds, 0 if it fails.

∈: belongs to · ¬: NOT · ∧: AND.
∃: at least one · ∀: every.
∅: no solution returned by this run.

stop(): end this attempt · terminate(): end the whole search · rand: random choice. “=” stores a value on lines 4, 7–9; the rule tests compare with 0 or 1.

Random sampling: start again each time

Draw a complete candidate, test it, then discard it if a rule fails.

1 · SampleChoose every variable’s value from its domain.
2 · TestCheck all constraints.
Zero conflicts? Return the solution.
3 · RepeatIf it fails, draw a fresh complete candidate.

Example: two independent draws

(0,1,0) → (1,2,0)

Order: X₁,X₂,X₃. First draw fails X₃<X₁; second draw satisfies all three rules.

In the generic loop

stop() = true

Skip the inner repair loop. Each attempt only samples and tests.

No information from the failed candidate guides the next draw. A finite number of draws can miss every solution.

Random walk: change one value at random

Keep the current candidate. Pick a variable and a new allowed value at random.

Conflicts: 1 → 2.

Sampling: replace the whole candidate.

Simulated annealing

Compare one proposal at two temperatures

In both panels, the current candidate has 1 conflict. We propose a candidate with 2 conflicts.

Current: h(a)=1 → Proposed: h(a′)=2

High temperature: more willing to explore

The worse proposal has a higher chance of being accepted.

If accepted → 2 conflicts

Replace the current candidate with the proposed one.

Low temperature: more selective

The same proposal has a higher chance of being rejected.

If rejected → keep 1 conflict

Keep the current candidate; try another proposal.

Temperature changes the chance of accepting the proposal. It does not change its conflict count. Both decisions remain possible.

Simulated annealing

Simulated annealing: accepting a worse move

Accept better or equal candidates. Sometimes accept a worse one to escape a trap. Use h(a) to compare their conflict scores.

Measure the score change

Δh = h(a′) − h(a)a: current assignment · a′: proposed assignment

Δh ≤ 0: accept a better or equal move.

For a worse move, Δh > 0

p = exp(−Δh / T)p: acceptance probability · T: positive temperature

Draw u uniformly from [0,1). Accept if u < p.

Here Δh=2. A positive T makes this worse move possible; cooling makes it less likely. The prime ′ marks the proposed assignment.

Simulated annealing

Cooling: explore first, then become more selective

An annealing schedule is simply the rule used to lower temperature during a run.

Early: warmer

More exploration

Worse moves are easier to accept, helping search leave a trap.

Later: cooler

More selective

The same worse move is less likely to be accepted.

The lab lowers temperature a little after each step. Cooling too fast can leave search stuck; a finite run can still miss a solution.
